## 一、环境依赖、启动与构建命令

### 1. 运行与开发依赖
- **Node.js**：`>= 20`
- **核心运行库**：`three ^0.187.0`、`gsap ^3.15.1`
- **构建与验证工具**：`typescript ~7.0.2`、`vite ^8.3.6`、`playwright-core ^1.65.1`

### 2. 常用命令
```bash
# 1. 安装项目依赖
npm install

# 2. 启动本地开发服务器（支持热更新 HMR，开发页面为 /dev.html）
npm run dev

# 3. 严格类型检查 + 生产构建 + 单文件独立 HTML 打包
#    开发入口 dev.html；完整独立游戏输出为根目录 index.html 和 dist/index.html
npm run build

# 4. 启动生产预览服务（监听 http://0.0.0.0:5173 / http://localhost:5173）
npm run preview

# 5. 运行五阶段闭环与移动端竖屏触控自动化冒烟验证
npm run test:e2e
```

## 七、指挥台无尽排行榜

- 首次进入直接游玩。第一次无尽挑战失败后填写指挥官名字，保存后解锁指挥台的「排行榜」页，并上传这次战绩；关闭登记页前刷新也会保留待登记战绩。
- 名字、匿名玩家身份和待上传成绩保存在当前浏览器。之后无需重复登记；可在排行榜中修改名字。清除浏览器存储或更换设备会使用新的匿名身份。
- 正式配置为游戏 `tdk`、榜单 `endless`，公开读取、允许游客提交、`best` 更新。排序依次为 `score`（完成波次）降序、`kills` 降序、`duration` 升序；用时为游戏内有效战斗秒数，不计暂停、指挥台及演出时间。
- 解锁后，无尽失败、重开、离开无尽关卡及页面关闭时会保留本局结果。上传失败不阻塞结算，排行榜提供手动重试；相同或较差成绩不会覆盖历史最好战绩。
- 排行榜使用 [网页小游戏接入指南](https://github.com/GOD-OF-PPT/common-game-ranking-list/blob/main/docs/web-game-integration.md) 的 HTTPS 接口。客户端配置见 `src/ranking/LeaderboardService.ts`，不包含管理员密钥或后端密钥。
- `tests/leaderboard.mjs` 覆盖首次无尽失败登记、存储、身份复用、并列排名、分页、失败重试、401、限流、安全显示和受限存储降级。CI 中拦截排行榜请求，不向正式榜写入测试成绩。
