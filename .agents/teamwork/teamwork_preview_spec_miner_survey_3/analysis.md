### 3.3 Deep Dive: Why `0px` Height Collapse Happens in `<agent-embed>` & What Still Needs Fixing for Side-Pane / Bookmark Iframes
1. **Why `0px` collapse occurs in adaptive-height iframes (`generative_ui` skill & browser layout rules)**:
   - `<agent-embed>` mounts the artifact inside an iframe whose height is derived from its content (`scrollHeight`), starting at `0px`.
   - As documented in the `generative_ui` skill: *"Never size an inline widget relative to the viewport: no `h-screen`, `min-h-screen`, `100vh`, or `height: 100%` on a top-level container. The frame's viewport is derived from your content, so these feed themselves and the widget collapses to a sliver."*
   - Because `#game-canvas` and `#ui-layer` are `position: absolute; inset: 0`, `#app` has `0px` intrinsic content height unless given an explicit pixel `height` or `min-height`.
2. **How the current repo (`src/style.css` + `src/main.ts`) prevents `0px` collapse in `<agent-embed>`**:
   - `html, body` omit `height: 100%` / `100vh` by default (`src/style.css:11-17`), and `#app` declares explicit `height: 580px` (`src/style.css:57`).
   - Only when `window.self === window.top` (`src/main.ts:14`) does JS add `html.is-top-window`, switching `html, body, #app` to `height: 100%`.
   - Empirically verified in `SURFACE_3_AGENT_EMBED_0PX_START`: even when the iframe starts at `height: 0px` with `sandbox="allow-scripts"`, `documentElement.scrollHeight` is immediately `580px` and WebGL initializes cleanly at `756x576`.
3. **Remaining Sizing Defect in Side-Pane Artifact Preview & `:5173` Bookmark Preview (`SURFACE_2_IFRAME_5173_920PX`)**:
   - When the user opens `Starforge Ark Cradle.url.json` (`http://localhost:5173`) OR opens `starforge_ark_cradle.html` in the **IDE Side-Pane Preview**, the host renders the page inside a **fixed-viewport `<iframe>`** (e.g., `1200x920`), so **`window.self === window.top` is `false`!**
   - Consequently, `html.is-top-window` is **not** added, clamping `#app` at `height: 580px` with `340px` of empty transparent space below in a `920px` side pane (and clipping bottom controls if the pane is `< 580px` tall).
   - **Clean Fix Recommendation for Implementation Phase**:
     - Distinguish `<agent-embed>` (`file:`/`about:srcdoc` where initial `window.innerHeight <= 600` or `0`) from **full-pane preview iframes** (`window.location.protocol.startsWith('http')` for `:5173`, OR initial `window.innerHeight > 600` before `#app` expands, since `#app` is `580px` so an auto-sized `<agent-embed>` iframe will have `innerHeight === 0` initially and `<= 580` after resize, whereas a side-pane preview iframe already has `innerHeight > 600`!).
     - Even when applying full-pane mode (`html.is-full-pane`), keep `min-height: 480px` on `#app` as a hard floor so it can **never** collapse to `0px` under any circumstances.
