## Logic Chain
1. Because `GameEngine` uses `preserveDrawingBuffer: false` AND overlays `#ui-layer` buttons styled with CSS `border: 2px solid #1a1033` (`rgb(26, 16, 51)`), naive full-viewport screenshot scanning would falsely pass `#1A1033` checks by matching DOM button borders even when 3D WebGL outlines are crushed to `rgb(9, 2, 31)`.
2. Sampling unobstructed 3D silhouettes (`x_css = 360, y_css = 95..185` and `pad_03` `(526, 404)` with tray closed) via **both** synchronous post-render `gl.readPixels` (pure WebGL buffer) and `page.screenshot({ clip })` (`node:zlib` PNG decode) eliminates DOM false positives while verifying end-user compositor output.
3. Hooking `gl.getUniformLocation` + `gl.uniformMatrix4fv` for perspective `projectionMatrix` (`Math.abs(P[11] + 1) < 0.01`) and `viewMatrix` inside `page.addInitScript` provides exact (`< 0.00001px`) opaque-box world-to-screen projection for arbitrary 3D bounding points (Entrance `(-14.85, 1.2, -3.2)`, Beacon foundation `(14.75, 0.18, 2.4)`, Beacon dish `(12.95, 2.55, 2.4)`, Supply Chest `(9.75, 0.5, 2.7)`) across all modes without touching private `GameEngine` fields.
4. Projecting the Return Beacon's `+1.8m` outer radius at its true physical foundation elevation **`y = 0.18`** (`(14.75, 0.18, 2.4)`) rather than `y = 1.2` avoids `+19.6px` of false elevated-camera perspective parallax, aligning `distScale ~ 1.10` (`x = 1420.0px <= 1424px`) cleanly with `plan.md` F16.
